# 常见问题

本文记录本地开发和自部署运行时常见的运维排障问题。这里的“当前机器”指运行 `backup-manager` 服务的机器；如果使用 Docker Compose，则通常指容器内部。

## 本地运行前需要安装哪些命令行工具？

**问题**

本地启动服务后，测试数据源、测试备份目标或执行备份任务时报缺少命令行工具。

**原因**

备份管理台会在运行机器上调用数据库客户端、SSH 工具和压缩工具。前端页面只是发起 API 请求，真正执行命令的是后端服务所在环境。

**处理方式**

本地运行前至少准备：

- Rust 工具链和 pnpm，用于构建和启动项目。
- MySQL 客户端工具：`mysqldump`、`mysqladmin`、`mysql`。
- PostgreSQL 客户端工具：`pg_dump`、`psql`。
- SQL Server 客户端工具：`sqlcmd`、`sqlpackage`。
- SSH 连接工具：`ssh`，Debian/Ubuntu 上通常来自 `openssh-client`。
- 备份上传工具：`rsync`。
- 如果备份目标使用 SSH 密码认证，还需要 `sshpass`。

Debian/Ubuntu 示例：

```bash
sudo apt-get update
sudo apt-get install openssh-client rsync sshpass default-mysql-client postgresql-client
```

SQL Server 的 `sqlcmd` 和 `sqlpackage` 通常需要按 Microsoft 官方方式额外安装，或挂载到自定义镜像/运行环境中。

macOS 示例：

```bash
brew install mysql-client libpq
brew install hudochenkov/sshpass/sshpass
```

macOS 上的 SQL Server 客户端工具也需要单独安装；安装后确保 `sqlcmd` 和 `sqlpackage` 在服务进程的 `PATH` 中，或通过环境变量指定绝对路径。

macOS 通常已经内置 `/usr/bin/ssh`。如果使用 Homebrew 安装的数据库客户端没有进入 `PATH`，需要按 Homebrew 提示补充环境变量，或通过项目支持的命令路径环境变量指定。

**验证命令**

```bash
command -v ssh
command -v rsync
command -v sshpass
command -v mysqldump
command -v mysqladmin
command -v mysql
command -v pg_dump
command -v psql
command -v sqlcmd
command -v sqlpackage
```

## “测试目标”报 `required command sshpass was not found` 怎么处理？

**问题**

在备份目标表单中选择 SSH 密码认证，点击“测试目标”时报：

```text
required command `sshpass` was not found. 当前使用 SSH 密码认证，请安装 sshpass；同时需要 openssh-client 可用。
```

**原因**

SSH 密码认证需要后端服务在当前机器上非交互式传递密码。项目通过 `sshpass` 调用 `ssh`，所以运行 `backup-manager` 的环境必须能在 `PATH` 中找到 `sshpass`。

**处理方式**

macOS 使用 Homebrew 安装：

```bash
brew install hudochenkov/sshpass/sshpass
```

Debian/Ubuntu 安装：

```bash
sudo apt-get update
sudo apt-get install openssh-client sshpass
```

安装后重新启动 `backup-manager`，确保服务进程能读取到新的 `PATH`。

**验证命令**

```bash
command -v ssh
command -v sshpass
sshpass -V
```

## SSH 密钥认证和密码认证分别需要哪些工具？

**问题**

备份目标支持密钥认证和密码认证，两种方式依赖的本机工具不同。

**原因**

密钥认证可以直接调用 `ssh` 并通过临时私钥文件连接远端；密码认证无法在非交互式服务进程里手动输入密码，因此需要 `sshpass`。

**处理方式**

- 使用密钥认证时，当前机器需要 `ssh`。
- 使用密码认证时，当前机器需要 `sshpass`，并且 `ssh` 也需要可用。
- 如果可以选择，生产环境更推荐密钥认证，便于权限收敛和自动化运行。

**验证命令**

```bash
command -v ssh
command -v sshpass
```

## 什么时候需要 `rsync`？

**问题**

“测试目标”成功了，但真正执行备份上传时可能仍然报缺少 `rsync`。

**原因**

“测试目标”主要验证 SSH 是否能连接、远端目录是否可写；它不会上传备份文件。实际执行备份任务时，目标适配器会使用 `rsync` 把本地生成的备份文件上传到远端目录。

**处理方式**

在运行 `backup-manager` 的环境安装 `rsync`：

```bash
sudo apt-get update
sudo apt-get install rsync
```

macOS 可以使用：

```bash
brew install rsync
```

如果使用 SSH 密码认证，实际上传还需要 `sshpass`。

**验证命令**

```bash
command -v rsync
rsync --version
```

## 使用 Docker Compose 时宿主机还需要安装 SSH 和数据库客户端工具吗？

**问题**

使用项目自带 Docker Compose 启动时，不确定依赖应该安装在宿主机还是容器里。

**原因**

命令行工具必须安装在运行 `backup-manager` 服务的环境中。项目自带的 `deploy/Dockerfile` 已经在最终镜像中安装数据库客户端、`openssh-client`、`rsync`、`sshpass` 和压缩工具。

**处理方式**

如果使用项目自带镜像和 Docker Compose，通常不需要在宿主机额外安装这些工具；宿主机只需要能运行 Docker。只有在宿主机直接执行 `cargo run -p backup-manager` 或 `make run` 时，才需要在宿主机安装运行依赖。

**验证命令**

容器运行后可以进入容器检查：

```bash
docker compose -f deploy/docker-compose.yml exec backup-manager command -v ssh
docker compose -f deploy/docker-compose.yml exec backup-manager command -v rsync
docker compose -f deploy/docker-compose.yml exec backup-manager command -v sshpass
```

## 数据库连接测试或备份报缺少 MySQL/PostgreSQL/SQL Server 工具怎么办？

**问题**

测试数据源或执行备份时报缺少 `mysqladmin`、`mysql`、`mysqldump`、`psql`、`pg_dump`、`sqlcmd` 或 `sqlpackage`。

**原因**

管理台本机执行模式会在运行 `backup-manager` 的环境调用数据库客户端工具：

- MySQL 连接测试使用 `mysqladmin`。
- MySQL 测试成功后拉取数据库列表使用 `mysql`。
- MySQL 备份使用 `mysqldump`。
- PostgreSQL 连接测试和拉取数据库列表使用 `psql`。
- PostgreSQL 备份使用 `pg_dump`。
- SQL Server 连接测试和拉取数据库列表使用 `sqlcmd`。
- SQL Server 备份使用 `sqlpackage` 导出 `.bacpac`。

**处理方式**

Debian/Ubuntu 示例：

```bash
sudo apt-get update
sudo apt-get install default-mysql-client postgresql-client
```

SQL Server 工具不包含在上述发行版通用包中，请按 Microsoft 官方文档安装 `sqlcmd` 和 `sqlpackage`，或将工具挂载到容器后通过环境变量指定路径。

如果客户端工具不在 `PATH` 中，可以通过环境变量覆盖路径：

- `MYSQLDUMP_PATH`
- `MYSQLADMIN_PATH`
- `MYSQL_PATH`
- `PG_DUMP_PATH`
- `PSQL_PATH`
- `SQLCMD_PATH`
- `SQLPACKAGE_PATH`

**验证命令**

```bash
command -v mysqldump
command -v mysqladmin
command -v mysql
command -v pg_dump
command -v psql
command -v sqlcmd
command -v sqlpackage
```

## 默认登录账号是什么？如何修改？

**问题**

首次本地启动后不知道用什么账号登录，或需要修改默认管理员账号。

**原因**

服务会先加载 `.env`，再读取进程环境变量。如果没有显式配置，开发默认账号是 `admin / admin123`。

**处理方式**

首次本地运行前复制环境变量文件：

```bash
cp .env.example .env
```

然后在 `.env` 中设置：

```env
ADMIN_USERNAME=admin
ADMIN_PASSWORD=admin123
```

生产环境必须改成强密码。

**验证命令**

```bash
grep -E '^(ADMIN_USERNAME|ADMIN_PASSWORD)=' .env
```

## 如何修改监听端口和前端默认备份目标路径？

**问题**

后端端口不是默认 `8080`，或希望新建备份目标时表单默认显示自己的远端目录。

**处理方式**

在项目根目录 `.env` 中设置：

```env
BIND_ADDR=0.0.0.0:8080
DEFAULT_TARGET_BASE_DIR=~/backups
```

如果使用 Vite 前端开发服务器，并且后端端口改成了其他值，还需要在 `web/.env` 中设置开发代理：

```env
VITE_API_PROXY_TARGET=http://127.0.0.1:8080
```

`BACKUPS_DIR` 是服务本机执行备份时使用的临时目录，和远端备份目标目录不是同一个配置。

## 为什么要妥善保存 `APP_SECRET`？

**问题**

部署时看到 `APP_SECRET` 配置，但不确定它丢失或更换会有什么影响。

**原因**

`APP_SECRET` 用于加密已保存的数据库密码、SSH 私钥或密码等敏感信息。如果保存过真实密钥后丢失或更换 `APP_SECRET`，已有敏感信息可能无法解密，相关数据源或备份目标需要重新配置密钥。

**处理方式**

- 生产环境首次部署前生成稳定的 `APP_SECRET`。
- 将 `APP_SECRET` 保存在密码管理器或部署密钥系统中。
- 不要把 `.env` 提交到 Git。
- 如果必须轮换 `APP_SECRET`，先确认已有敏感配置的迁移或重录方案。

**验证命令**

```bash
grep -E '^APP_SECRET=' .env
```
