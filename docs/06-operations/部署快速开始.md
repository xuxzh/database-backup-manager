# 部署快速开始

本文面向服务器自部署场景，说明如何在 Windows、Linux 和 macOS 上部署数据库备份管理台。

推荐优先使用 Docker Compose 部署。项目自带镜像会构建前端产物和后端二进制，并在容器内安装 MySQL、PostgreSQL、SSH、rsync、sshpass 和 gzip 等常用运行依赖，部署行为在不同系统上更一致。

## 部署前准备

部署机器需要能访问要备份的数据库和远端备份目标。

如果使用 Docker Compose：

- Windows：安装 Docker Desktop，并启用 WSL 2 后端。
- Linux：安装 Docker Engine 和 Docker Compose Plugin。
- macOS：安装 Docker Desktop。

如果直接在宿主机运行源码：

- 安装 Rust 工具链。
- 安装 Node.js，并通过 Corepack 启用 pnpm。
- 安装数据库客户端工具、SSH 工具和 rsync。具体工具清单见 [常见问题](./常见问题.md)。

生产环境部署前请准备稳定的配置：

```env
APP_SECRET=请替换为长期保存的随机密钥
ADMIN_USERNAME=admin
ADMIN_PASSWORD=请替换为强密码
BIND_ADDR=0.0.0.0:8080
DATA_DIR=data
BACKUPS_DIR=backups
DEFAULT_TARGET_BASE_DIR=~/backups
```

`APP_SECRET` 用于加密已保存的数据库密码、SSH 私钥或密码。保存过真实密钥后，不要丢失或随意更换。

## 方式一：Docker Compose 部署

适用于 Windows、Linux 和 macOS，也是推荐方式。

### 1. 获取代码

```bash
git clone git@github.com:xuxzh/database-backup-manager.git database-backup-manager
cd database-backup-manager
```

如果服务器上已经有代码，进入项目根目录即可。

### 2. 修改生产配置

编辑 `deploy/docker-compose.yml`，至少修改管理员密码和 `APP_SECRET`：

```yaml
environment:
  ADMIN_USERNAME: admin
  ADMIN_PASSWORD: change-this-password
  APP_SECRET: change-this-secret-before-production
```

如果需要修改访问端口，例如宿主机使用 `18080`：

```yaml
ports:
  - "18080:8080"
```

### 3. 启动服务

```bash
cd deploy
docker compose up -d --build
```

首次启动会构建前端、编译 Rust 后端并创建容器。

### 4. 访问管理台

浏览器打开：

```text
http://服务器IP:8080
```

如果改过端口，使用修改后的宿主机端口。

### 5. 查看日志和状态

```bash
docker compose ps
docker compose logs -f backup-manager
```

### 6. 停止服务

```bash
docker compose down
```

默认 Compose 配置使用 Docker volume 保存元数据和本地备份临时文件：

- `backup-manager-data`：SQLite 元数据。
- `backup-manager-backups`：服务本机备份目录。

不要在确认已备份数据前删除这些 volume。

## 方式二：Linux 直接运行

适用于希望直接在 Linux 服务器上运行二进制的场景。

Linux 直接运行有两种常见方式：

- 在目标服务器拉取源码并构建。
- 在一台 Linux 构建机上打包发布产物，再复制到其他 Linux 服务器运行。

如果需要部署多台服务器，推荐使用第二种方式。目标服务器不需要安装 Rust、Node.js、pnpm，也不需要拉取源码。

### 1. 安装基础依赖

Debian/Ubuntu 示例：

```bash
sudo apt-get update
sudo apt-get install -y build-essential pkg-config curl git openssh-client rsync sshpass default-mysql-client postgresql-client gzip
```

SQL Server 数据源还需要安装 `sqlcmd` 和 `sqlpackage`。如果工具不在 `PATH` 中，可通过 `SQLCMD_PATH` 和 `SQLPACKAGE_PATH` 指定绝对路径。

如果是“构建机打包，目标机运行”的部署方式，目标服务器只需要运行时依赖：

```bash
sudo apt-get update
sudo apt-get install -y openssh-client rsync sshpass default-mysql-client postgresql-client gzip
```

### 2. 源码构建：安装 Rust、Node.js 和 pnpm

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
```

使用系统包管理器、NodeSource、nvm 或 Node.js 官方方式安装 Node.js 后，启用 pnpm：

```bash
node --version
corepack enable
```

### 3. 源码构建：准备配置

```bash
cp .env.example .env
```

编辑 `.env`，至少修改：

```env
APP_SECRET=请替换为长期保存的随机密钥
ADMIN_USERNAME=admin
ADMIN_PASSWORD=请替换为强密码
BIND_ADDR=0.0.0.0:8080
```

### 4. 源码构建：构建前端和后端

```bash
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
```

### 5. 源码构建：启动服务

```bash
./target/release/backup-manager
```

### 6. 构建机打包：生成 Linux 发布包

在构建机上执行：

```bash
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
```

创建发布目录：

```bash
rm -rf release/backup-manager
mkdir -p release/backup-manager/web
cp target/release/backup-manager release/backup-manager/
cp .env.example release/backup-manager/.env.example
cp -R web/dist release/backup-manager/web/
```

打包：

```bash
cd release
tar -czf backup-manager-linux-x86_64.tar.gz backup-manager
```

发布包目录必须保留这个结构：

```text
backup-manager/
  backup-manager
  .env.example
  web/
    dist/
      index.html
      assets/
```

后端会从当前工作目录下的 `web/dist` 托管前端页面，因此不能只复制 `backup-manager` 二进制。

构建机和目标服务器需要使用兼容的系统和 CPU 架构。例如，在 `x86_64 Linux` 上构建的产物通常用于其他 `x86_64 Linux` 服务器；如果目标服务器是 ARM64，需要单独构建 ARM64 产物。

### 7. 构建机打包：部署到目标服务器

把发布包复制到目标服务器：

```bash
scp release/backup-manager-linux-x86_64.tar.gz user@server:/tmp/
```

在目标服务器解压：

```bash
sudo mkdir -p /opt/database-backup-manager
sudo tar -xzf /tmp/backup-manager-linux-x86_64.tar.gz -C /opt/database-backup-manager --strip-components=1
cd /opt/database-backup-manager
sudo cp .env.example .env
```

编辑 `/opt/database-backup-manager/.env`，至少修改：

```env
APP_SECRET=请替换为长期保存的随机密钥
ADMIN_USERNAME=admin
ADMIN_PASSWORD=请替换为强密码
BIND_ADDR=0.0.0.0:8080
DATA_DIR=data
BACKUPS_DIR=backups
```

启动验证：

```bash
cd /opt/database-backup-manager
./backup-manager
```

### 8. 使用 systemd 托管 Linux 进程

生产环境建议使用 systemd 托管进程。示例：

```ini
[Unit]
Description=Database Backup Manager
After=network.target

[Service]
WorkingDirectory=/opt/database-backup-manager
ExecStart=/opt/database-backup-manager/backup-manager
Restart=always
EnvironmentFile=/opt/database-backup-manager/.env

[Install]
WantedBy=multi-user.target
```

保存为 `/etc/systemd/system/backup-manager.service` 后执行：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now backup-manager
sudo systemctl status backup-manager
```

如果使用源码构建方式，并且希望直接运行 `target/release/backup-manager`，请把 `ExecStart` 改成实际二进制路径，同时确保 `WorkingDirectory` 指向包含 `web/dist` 的项目根目录。

## 方式三：macOS 直接运行

适用于在 Mac mini、Mac Studio 或本机长期运行的场景。服务器部署仍更推荐 Docker Compose。

### 1. 安装依赖

```bash
brew install rustup node mysql-client libpq rsync
brew install hudochenkov/sshpass/sshpass
rustup-init
corepack enable
```

Homebrew 安装的 `mysql-client` 和 `libpq` 可能不会自动加入 `PATH`。可以在 `.env` 中指定工具路径：

```env
MYSQLDUMP_PATH=/opt/homebrew/opt/mysql-client/bin/mysqldump
MYSQLADMIN_PATH=/opt/homebrew/opt/mysql-client/bin/mysqladmin
MYSQL_PATH=/opt/homebrew/opt/mysql-client/bin/mysql
PG_DUMP_PATH=/opt/homebrew/opt/libpq/bin/pg_dump
PSQL_PATH=/opt/homebrew/opt/libpq/bin/psql
```

Intel Mac 的 Homebrew 路径通常是 `/usr/local`，请按实际安装路径调整。

SQL Server 数据源还需要额外安装 `sqlcmd` 和 `sqlpackage`。

### 2. 构建并运行

```bash
cp .env.example .env
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
./target/release/backup-manager
```

浏览器访问：

```text
http://127.0.0.1:8080
```

如果需要作为后台服务长期运行，可使用 launchd、进程管理器，或改用 Docker Compose。

### 3. macOS 构建机打包部署

可以在一台 macOS 构建机上打包，然后分发到其他 macOS 机器运行。目标机器不需要安装 Rust、Node.js、pnpm，但仍需要安装运行时工具，例如数据库客户端、`ssh`、`rsync`、`sshpass` 和 `gzip`。

构建机执行：

```bash
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
```

创建发布包：

```bash
rm -rf release/backup-manager
mkdir -p release/backup-manager/web
cp target/release/backup-manager release/backup-manager/
cp .env.example release/backup-manager/.env.example
cp -R web/dist release/backup-manager/web/
cd release
tar -czf backup-manager-macos-arm64.tar.gz backup-manager
```

如果构建机是 Intel Mac，请把包名改成 `backup-manager-macos-x86_64.tar.gz`。Apple Silicon 和 Intel Mac 的产物不能直接混用，除非显式配置交叉编译或通用二进制。

目标机器部署：

```bash
sudo mkdir -p /opt/database-backup-manager
sudo tar -xzf backup-manager-macos-arm64.tar.gz -C /opt/database-backup-manager --strip-components=1
cd /opt/database-backup-manager
sudo cp .env.example .env
./backup-manager
```

macOS 同样要求运行目录中存在 `web/dist`，否则后端无法托管前端页面。

## 方式四：Windows 部署

Windows 上推荐使用 Docker Desktop 或 WSL 2 部署。直接在原生 Windows 进程中运行时，`sshpass`、`rsync`、数据库客户端和路径兼容性更容易出现差异，不建议作为生产部署首选。

### Docker Desktop 部署

1. 安装 Docker Desktop。
2. 启用 WSL 2 后端。
3. 在 PowerShell 或 Windows Terminal 中进入项目目录。
4. 执行：

```powershell
cd deploy
docker compose up -d --build
```

访问：

```text
http://localhost:8080
```

### WSL 2 部署

在 WSL 2 的 Ubuntu 环境中，按本文 “Linux 直接运行” 或 “Docker Compose 部署” 执行即可。

建议把项目放在 WSL 文件系统中，例如：

```text
~/database-backup-manager
```

避免放在 `/mnt/c/...` 下运行构建和备份任务，以减少文件权限和 I/O 性能问题。

### 原生 Windows 源码构建

如果确实需要在原生 Windows 上运行，可使用 PowerShell 构建：

```powershell
copy .env.example .env
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
.\target\release\backup-manager.exe
```

运行前需要安装 Rust、Node.js、pnpm，以及 Windows 可用的数据库客户端、OpenSSH 和 rsync。SQL Server 工具通常可直接安装 Windows 版本的 `sqlcmd` 和 `sqlpackage`。

原生 Windows 上 `sshpass` 支持不如 Linux/macOS 常见。如果需要 SSH 密码认证或稳定的 rsync 上传，建议改用 Docker Desktop 或 WSL 2。

### 原生 Windows 构建机打包部署

可以在一台 Windows 构建机上打包，再复制到其他 Windows 机器运行。目标机器不需要安装 Rust、Node.js、pnpm，但仍需要运行时工具。

构建机执行：

```powershell
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
```

创建发布目录：

```powershell
Remove-Item -Recurse -Force release\backup-manager -ErrorAction SilentlyContinue
New-Item -ItemType Directory -Force release\backup-manager\web | Out-Null
Copy-Item target\release\backup-manager.exe release\backup-manager\
Copy-Item .env.example release\backup-manager\.env.example
Copy-Item -Recurse web\dist release\backup-manager\web\
```

打包：

```powershell
Compress-Archive -Path release\backup-manager -DestinationPath release\backup-manager-windows-x86_64.zip -Force
```

目标机器解压后进入发布目录：

```powershell
copy .env.example .env
.\backup-manager.exe
```

发布目录必须保留：

```text
backup-manager\
  backup-manager.exe
  .env.example
  web\
    dist\
      index.html
      assets\
```

如果要长期运行，可以使用 Windows 服务管理工具、任务计划程序或 NSSM 等进程托管工具。生产部署更推荐 Docker Desktop 或 WSL 2，以减少命令行工具兼容性问题。

## 反向代理和 HTTPS

生产环境通常会在服务前放置 Nginx、Caddy 或云厂商负载均衡。

后端默认监听：

```env
BIND_ADDR=0.0.0.0:8080
```

反向代理只需要转发到该端口。示例 Nginx 配置：

```nginx
server {
    listen 80;
    server_name backup.example.com;

    location / {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

HTTPS 证书可由 Nginx、Caddy、Traefik 或云负载均衡统一管理。

## 升级流程

Docker Compose 部署：

```bash
git pull
cd deploy
docker compose up -d --build
```

直接运行部署：

```bash
git pull
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
```

构建机打包部署：

```bash
cd web
pnpm install
pnpm build
cd ..
cargo build --release -p backup-manager
rm -rf release/backup-manager
mkdir -p release/backup-manager/web
cp target/release/backup-manager release/backup-manager/
cp .env.example release/backup-manager/.env.example
cp -R web/dist release/backup-manager/web/
```

将新发布包复制到目标服务器后，替换二进制和 `web/dist`，保留目标服务器上的 `.env`、`data/` 和 `backups/`。

然后重启进程或 systemd 服务：

```bash
sudo systemctl restart backup-manager
```

升级前建议备份：

- `.env`
- `DATA_DIR` 对应目录，默认是 `data/`
- 如果本地备份目录中保留了重要文件，也备份 `BACKUPS_DIR` 对应目录，默认是 `backups/`

## 部署后检查清单

完成部署后建议逐项检查：

- 可以打开登录页。
- 可以使用生产管理员账号登录。
- 页面中可以创建并测试数据库源。
- 页面中可以创建并测试备份目标。
- 可以手动触发一次备份任务。
- 执行历史中可以看到任务状态和日志。
- 重启服务后配置和历史记录仍然存在。

常用检查命令：

```bash
curl -I http://127.0.0.1:8080
```

Docker Compose：

```bash
docker compose -f deploy/docker-compose.yml logs --tail=100 backup-manager
```

systemd：

```bash
journalctl -u backup-manager -n 100 --no-pager
```
